# Alcance propuesto: crocoblock-pp-cli

Estado: alcance completo aprobado por Bobe; todavía no hay CLI generado ni validación de producto terminado. Fecha de investigación: 20 de octubre de 2026, America/Monterrey.

La solicitud cubre JetEngine, formularios JetFormBuilder, reservas JetBooking/JetAppointment y filtros JetSmartFilters. Se proponen **55 capacidades base + 6 análisis nuevos = 61 capacidades**. Las once funciones del MCP nativo de JetEngine quedan incluidas. Las funciones genéricas del framework (doctor, ayuda, JSON, selección de campos, códigos de salida, MCP y gestión de configuración) son infraestructura adicional y no inflan el conteo.

Las seis funciones nuevas requieren Go escrito a mano; ninguna se resuelve únicamente mediante generación de endpoints. Sus adaptadores de captura, normalización, procedencia y cobertura también forman parte del trabajo comprometido. No se proponen placeholders ni stubs.

## Evidencia y acceso

Paquetes oficiales descargados desde la cuenta autenticada y activos en un entorno development nuevo de WP Engine: JetEngine 3.9.0, JetBooking 4.1.3.1, JetAppointment 2.5.3, JetSmartFilters 3.8.6.2 y JetFormBuilder 3.6.7. Autenticación REST por usuario WordPress + Application Password sobre HTTPS. La sesión de Crocoblock sirve para obtener paquetes; no es la credencial de ejecución del CLI.

Comprobado: MCP tools/list con once herramientas; formularios crear/leer/editar/papelera y lectura anónima denegada; CCT crear/leer/editar/eliminar; filtros crear/leer/editar/papelera y conservación de metadatos. Las pruebas descritas son de contratos del proveedor, no dogfood de un CLI que aún no existe. Las pruebas de reservas, relaciones, captura de registros y reindexación se documentan por separado; no se presenta una lista vacía como prueba de CRUD.

## Contrato de implementación y límites

- Las escrituras admiten `--dry-run`, validación del esquema descubierto y verificación posterior. Un HTTP 200, una cadena de éxito o `success: true` por sí solos no demuestran persistencia. Las lecturas de filtros usan POST pero deben rechazar las claves que mutan la colección.
- Los análisis nuevos leen sólo SQLite; rechazan `--data-source live`, muestran sitio, hora, versiones, alcance y cobertura. Si faltan páginas, permisos, campos o inventarios, informan `unknown` o error, nunca un informe vacío que parezca aprobación. Las comparaciones entre sitios requieren claves explícitas y compatibles.
- `sync` debe captar por adaptadores, con recursos documentados, `--resources`, `--db`, `--full` y `--strict`. Los parámetros específicos de CCT, campos y muestras de registros se declararán sin confundirlos con paginación. No se promete sincronización incremental sin cursor comprobado.
- Los snapshots estructurales omiten secretos y valores de acciones. Para uso de campos se captan nombres y presencia, no valores de envíos. CCT y restauraciones de metadatos requieren campos seleccionados, almacenamiento privado y exclusión de claves sensibles por defecto. Nunca se guardan Application Passwords ni licencias en snapshots, ejemplos o recibos.
- `fields` opera sólo con campos JetEngine que el sitio ya expone por REST de WordPress. Descubre capacidades y rechaza campos no expuestos; no instala WPMCP ni un bridge. Restaurar exige un snapshot propio y comprobar que no se pisan cambios posteriores inadvertidamente.
- `filters reindex` usa SSH/WP-CLI configurado explícitamente. Verifica la URL del sitio y la disponibilidad del método público del plugin, ejecuta una reconstrucción y registra su resultado. Sin SSH puede usarse el resto de la integración; este comando debe explicar la dependencia ausente. No utiliza cookies ni inventa una ruta REST de reindexación.
- `filters impact` sólo conoce las escrituras registradas y dependencias comprobadas; no certifica frescura global ni cobertura de cambios ajenos. Los filtros/proveedores que no puedan resolverse se marcan desconocidos.
- Reservas por noche y citas por horario mantienen modelos separados. Política de estados, límites, zona horaria y capacidad explícita; no se promete disponibilidad universal ni reprogramación automática. Los workflows existentes del sitio pueden producir efectos al escribir; se previsualiza la operación y no se crean pedidos por defecto.
- Crear un formulario lo deja en borrador por defecto. No se incluye envío de formularios, cobros, correo real, publicación automática, credenciales Zoom/Google Calendar ni administración de licencias/compras. No se incluye el resto del catálogo de JetPlugins.
- Configuración y creación de estructuras cubren el MCP nativo enumerado. La primera versión no promete CRUD universal de cualquier ajuste privado de wp-admin. Las relaciones existentes admiten lectura y edición de aristas; crear nuevas definiciones de relación no está incluido.
- En JetEngine 3.9.0 el PUT parcial de CCT preservó los campos omitidos en la prueba. La advertencia documental contraria se conserva como discrepancia de versión, no como fallo demostrado del plugin actual.

## Criterios antes de considerarlo listo

Compilación e instalación local, correspondencia mecánica de cada fila con ayuda real, pruebas de errores y paginación, comprobaciones locales con conjuntos que detecten problemas y conjuntos sanos, prueba en vivo de cada familia de escritura con fixtures desechables y limpieza, revisión de salida/redacción, revisión de código y gates Printing Press. No se publicará el CLI ni se promocionará como listo con placeholders o pruebas pendientes.
